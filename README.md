# 映库 · Yingku

一个 Go 程序，将「浏览来源 → 扫描目录并识别作品和分集 → 在线匹配并确认作品 → 直接入库或下载 → 补充详情 → 媒体库与播放」串起来。当前版本 0.13.17。

## Docker / Dokploy

已提供 `Dockerfile`、`compose.yaml` 和 `.env.example`，详见 [容器部署说明](DEPLOYMENT.md)。容器默认监听 `0.0.0.0:8787`，配置与资料保存到 `/config`，已有视频和网盘下载都可以使用 `/media`。默认只需持久挂载这两个目录，更新镜像后继续使用。需要单独保护已有视频时，也可自行增加 `/imports` 只读挂载，并非必需。

在 Dokploy 中新建 **Application**，连接源码仓库，构建类型选择 **Dockerfile**，路径填 `Dockerfile`，构建上下文填 `.`。把配置和视频分别持久挂载到 `/config` 和 `/media`，域名或端口映射指向容器端口 `8787`。`YINGKU_PUBLIC_URL` 可留空。也可以使用 `compose.yaml` 部署。`data/`、真实 `.env` 和视频留在部署机器上；Git 提交源码和部署模板即可。当前只支持一个实例；局域网投屏的容器网络要求见部署文档。

## 立即使用（Windows）

1. 双击同目录下的 **启动映库.cmd**。程序会打开浏览器。
2. 默认无需填写资料 API Key。本地视频直接使用原路径；网盘下载或复制整理时，再确认保存目录。
3. 在「来源」添加百度网盘、夸克网盘、WebDAV 或本地目录。首次试用可以先添加一个包含 MP4 视频的本地目录。
4. 进入作品或季目录，勾选视频，点击「导入所选」。
5. 选择电影或电视剧，确认片名、年份和季数。可以直接搜索公开资料并选中正确作品，无需 Key。
6. 预览文件与季集的对应关系、保存位置；有问题时修改集号并更新预览。
7. 本地默认点击「加入媒体库」即可播放，不复制、不改名、不移动。网盘或主动选择的本地复制会创建任务，完成的集数可播放。

浏览器地址：[http://127.0.0.1:8787](http://127.0.0.1:8787)。关闭网页不会停止服务；在运行窗口按 Ctrl+C 停止程序。再次启动会保留资料和进度。服务已在运行时，重复双击启动文件会打开同一媒体库，不会再报端口占用。若端口被其他程序或另一个媒体库使用，会提示更换端口。

也可以在「来源」打开一个总文件夹，点击 **扫描整个目录**，一次识别其中的多部作品和所有季。先确认在线作品，再检查预览并入库。

## 扫描后先匹配作品

- 文件名或 AI 识别结果明确标注为「文件名推测 / AI 推测 · 未匹配」，不会因识别置信度高而显示匹配成功。
- 扫描完成后自动检索所选作品，同时最多检索两部。每部作品展示候选海报、名称、年份、简介、资料来源及来源链接。找到候选只表示待确认；点击「确认此作品」才显示「已确认匹配」，并更新作品名称和年份。
- 确认结果绑定资料来源和作品编号，导入预览、保存目录和后续详情补全沿用这次选择。修改名称、年份或类型会清除旧匹配，需要重新确认。已确认匹配即使完整资料暂时获取失败，也会保留作品编号和候选基本资料。
- 资料源不可用、没有结果或想手动整理时，可明确选择「暂不匹配，按当前名称入库」。这次入库不会再自动猜测在线作品；之后仍可在作品详情里手动匹配。批量扫描中每个已选作品都需要确认候选或选择暂不匹配，才可检查导入预览。
- 默认仍使用无需 Key 的公开资料，配置 TMDb 后优先使用 TMDb；TMDb 未找到候选时补充检索公开资料，候选始终标注实际来源。Key 无效、接口或网络错误仍明确报错，不冒充“没有结果”。AI 不负责联网核实，当前没有直接抓取 IMDb 或接入豆瓣在线刮削。匹配操作不下载视频、不创建媒体库条目；扫描记录和确认信息暂存于服务内存，重启后需要重新扫描。

## 媒体库与作品页面

- 媒体库以海报墙展示，顶部按全部、电影和电视剧切换。支持按片名、原名、年份和类型搜索，以及最近加入、名称和年份排序；继续观看使用带缩略图与进度的横向列表。
- 点击海报进入独立作品页面，不再打开作品详情弹窗。页面可直接收藏链接、刷新和使用浏览器前进后退；返回媒体库会恢复搜索、排序与列表位置。
- 作品页展示大海报、背景图、播放入口和投屏入口。电视剧按本机已有季展示季卡与分集缩略图；“作品资料”和“演职人员”保留完整刮削信息。文件名、大小和字幕操作收在“文件与字幕”中。
- “补全资料”和“匹配作品”位于详情页的更多操作中。来源、下载任务和设置可通过顶部图标进入。
- 播放使用填满窗口的沉浸式播放器，关闭后回到作品或原列表。来源配置、导入确认和投屏设备选择继续使用操作对话框。海报与剧照只展示实际资料，不向媒体库加入演示作品。

## AI 目录识别（可选）

AI 按最多 80 个视频分批识别。识别成功的文件默认勾选，多个批次合并为同一部剧时也会保留勾选状态；低置信度作品组仍需人工核对后选择。支持“全选已识别视频”和“取消全选”，只调整已归类文件，不自动归入待确认文件，也不额外调用 AI。0.13.1 修复了后续批次文件追加时漏设勾选状态的问题。

1. 在「设置 → AI 文件识别」启用功能，填写 **AI 端点、Key、模型名称**，保存后点击「测试 AI 连接」。不带鉴权的本机服务可以留空 Key。
2. 端点支持 `https://服务地址/v1` 或完整的 `/chat/completions` 地址。采用 OpenAI 兼容的 Chat Completions，优先请求 JSON mode；接口明确不支持该选项时，以普通 JSON 提示重试一次。实际兼容程度取决于服务商和模型。
3. 在来源里选择一个总文件夹，点击「扫描整个目录」，选择 AI 识别。目录内可以有多部电影、电视剧和多个季；识别按每批最多 80 个文件分批请求并显示进度。
4. 核对作品名、类型、年份、所属剧集和每个文件的季集号，并确认在线候选或明确选择暂不匹配。合并集可以填写起始集和结束集；无法确定的文件放在待确认区，支持手动归类。
5. 点击「检查导入预览」。修改或取消勾选有冲突的文件后，再确认入库。本地默认原地使用视频；只有主动选择复制整理时才显示保存目录。网盘来源会创建下载任务。

AI 接收的是所选目录的名称、视频相对路径及文件编号，用于理解文件命名；原视频、NFO 内容、来源授权和电脑绝对路径不发送给模型。调用可能消耗服务商额度。AI 的名称、季集和分组是建议，服务端会校验文件编号、季集范围和重复内容，低置信度组默认不选中。年份仅使用文件名和目录中明确出现的值；准确日期、简介、海报和演职人员继续由资料源补充。

Key 使用本机密钥加密保存，浏览器只显示是否已保存。留空保留同一服务的 Key，切换服务商主机时会清除旧 Key，需要重新填写。测试连接使用一个合成文件名，不读取你的影片内容。AI 请求不跟随重定向，不回显服务商原始错误中的凭据；公网端点使用 HTTPS，本机和内网可用 HTTP。

没有 AI 配置时仍可使用本地命名识别。AI 接口失败会保留原识别结果；可取消或重试。扫描记录在服务内存中临时保留，重启后可重新扫描；已入库的作品和任务正常保存在资料库。批量入库前会检查所有选中的分组，实际提交期间遇到文件变化或网络错误时，逐组报告已完成和未完成情况。

首次支持最多 1000 个视频、1200 个目录、20 层子目录；更大的库可按分类分批扫描。新接口与本地兼容测试服务完成了联调，未代替你验证任意第三方服务的真实模型效果。参考：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 手机访问与 DLNA 投屏

1. 启动后默认统一监听 0.0.0.0:8787，本机打开 http://127.0.0.1:8787，手机打开 http://电脑的局域网IP:8787。「设置 → 手机访问与 DLNA 投屏」会列出可用地址，无需再开启额外监听或填写第二端口。
2. 「需要访问密码」为可选项：不勾选时手机直接使用；勾选时设置至少 10 个字符的密码。已有密码保护的配置升级后会继续保留。网页访问保护只能在运行映库的电脑上通过本机地址修改。
3. 电脑、手机、电视连接同一家用网络，电视开启 DLNA 媒体接收。用手机打开影片播放器，点击「投屏到电视」，搜索并选择电视。
4. 选择电视后进入独立的「电视遥控」页面（`#cast`），提供播放、暂停、上下集、连播开关、停止、进度和设备支持的音量控制。页面没有关闭叉号，Esc 不会关掉遥控；可以返回播放器或其他页面，再从底部投屏提示进入。刷新网页会恢复当前会话，离开遥控页不停止电视。服务端每隔数秒读取电视状态并保存进度。

从电视遥控返回播放器时，会重新同步电视当前的集数与位置，并以暂停状态打开；电视已切到下一集时，网页会跟随该集。暂存的旧网页播放器不再写回进度；播放会话使用独立的进度归属标记，延迟到达的旧网页请求和旧电视会话不会覆盖后续播放。网页恢复播放会读取最新保存位置，继续观看优先使用最近实际观看的文件。电视若不能报告进度，仍只能使用最后成功保存的位置。

网页、视频与 DLNA 播放地址共用实际监听端口。默认监听全部 IPv4 网卡；如只需本机使用，可用 -addr 127.0.0.1:8787 启动，也可以通过 -addr 修改统一端口。密码只用于网页访问控制，与 DLNA 投屏无关，也不负责加密视频。免登录时，同一局域网内能访问该地址的设备都能浏览、播放和管理媒体库；来源和一般设置也可修改，访问保护仍仅允许在服务端本机修改。启用密码保护时，密码通过 PBKDF2-SHA256 校验，登录会话使用 HttpOnly Cookie；更改密码或切换保护模式会清除原有登录。取消密码要求会保留已保存的密码，以便之后重新启用。电脑本机可直接管理。密码与影片通过局域网 HTTP 传输，此模式适用于可信家用网络，不是公网部署或反向代理登录方案。无需新增进程或安装电视专用客户端。

「设置 → 手机访问与 DLNA 投屏 → 访问与投屏地址」提供两个可选配置：“访问地址”只用于展示，留空不影响 IP 或反代域名访问；“投屏回连地址”决定发给电视的视频链接，留空时自动选择通往电视的局域网地址。容器映射端口时可填写 `http://服务器局域网IP:映射端口`，保存后对新的投屏会话生效。它不负责 SSDP 设备发现；反代域名也不会自动替代电视的局域网回连地址。

本版实现 DLNA/UPnP 的设备发现与播放控制，不要求品牌名单，也不向电视共享整份来源配置。电视通过一个随机、仅限当前视频的临时地址读取文件，支持 HEAD 与 HTTP Range；停止投屏后该地址失效，最长有效 24 小时。搜索只读取响应设备自身的描述和控制地址，不跟随跳转。实现使用 [UPnP AVTransport 标准](https://openconnectivity.org/developer/specifications/upnp-resources/upnp/mediaserver4-and-mediarenderer3/)。

视频直接交给电视解码，暂不转码，不传送外置字幕；格式和可用遥控功能以电视实际支持为准。只支持屏幕镜像、AirPlay 或 Cast 而没有 DLNA 视频接收能力的设备不会出现。当前不提供电视端主动浏览整个媒体库、AirPlay 或 Google Cast。

电视剧投屏遥控提供上一集、下一集与独立的“自动播放下一集”开关（默认开启，网页会记住选择）。按当前作品的季、集顺序选择，可跨季并识别合并多集文件，不跳过相邻未入库视频。电视能接受 `SetNextAVTransportURI` 且能报告当前播放地址时，服务端预备一个下一集地址供电视衔接；不支持时由服务端根据播放状态和实际进度判断播完，再发送下一集。手机关屏、关闭网页或收起遥控不影响服务端监测。明确点击“停止投屏”、暂停、中途停止或切换到其他应用内容不会触发接续；电视不提供足够的结束信息时保守停下，不仅根据 `STOPPED` 猜测播完。设备遥控器的“下一集”能否使用取决于其投屏接收器，不能保证所有电视一致。仅授权当前文件、预备的一个下一集及控制切换中的目标文件；关闭连播或停止时撤销预备读取权限。

连播会话保存在服务运行期间；映库服务重启后需重新投屏。部分电视将“自然结束”和“手动停止”报告为相同状态，临近片尾且状态信息完全相同时无法可靠区分；接收器兼容性仍需实机确认。

DLNA 发现依赖同一局域网的 IPv4 多播。电脑防火墙需要允许映库在专用网络通信；虚拟机、容器和访客 Wi-Fi 的网络隔离可能影响搜索。服务端放在家中电脑或 NAS 才能直接搜索家中的电视；云服务器不能直接发现家里设备。登录、受限视频读取、进度和遥控已用模拟接收端验证，真实电视及无线网络兼容性仍需实机测试。

## 已实现

- Go 服务端，网页通过 `go:embed` 内嵌，二维码库随程序编译；运行时没有 npm、Node、Python 或额外数据库服务依赖。
- 本地目录、WebDAV 目录、百度网盘开放平台目录读取；来源保存前测试连接。
- 同一作品导入、数字顺序文件排序、常见 SxxExx / EPxx / 第xx集 / 数字文件名识别，以及逐文件修正季集。
- 电视剧按“剧 → 季 → 集”归组。优先匹配资料源作品编号，缺少编号时按剧名和整剧首播年份匹配；一边年份为空不再拆剧。同名且身份不确定时，可在“所属剧集”中手动选择或新建独立剧集。
- 后续季沿用已有剧集的名称和首播年份，下载整理到同一剧集目录下的不同季；本地原地入库保持源文件路径。支持从 Season 02、S02、第二季等目录识别季数。
- 导入前预览、重复来源文件跳过、目标位置冲突检查，不覆盖已有视频。
- 本地原地入库；复制整理为可选操作。网盘后台下载或本地复制支持 1–4 个并行任务、暂停、继续和失败后重试。
- 临时文件与可播放文件分开；HTTP 服务器提供可靠校验信息时可断点续传。远端忽略 Range 时重新下载，不拼接不可靠内容。
- 优先复用本地 NFO、海报、分集资料。默认通过维基百科、Wikidata 和 TVmaze 搜索和补充在线资料；TMDb 为高级可选来源。图片缓存到本机。
- 刮削失败与下载失败分别记录，重新刮削不重复下载视频。
- 详情页分为剧集/视频文件、作品资料和演职人员。支持原名、首播/上映日期、各季年份与播出日期、状态、参考时长、分级、地区、语言、主创、制作公司、带来源的评分、人物照片与角色、分集简介/日期/时长，以及外部资料链接；字段按来源实际提供情况展示。
- 媒体库搜索、电影/电视剧筛选、季/集详情、浏览器直接播放、HTTP Range 跳转、观看进度保存。
- UTF-8 SRT / VTT 字幕添加；本地直接入库和复制时均收集同名字幕，原字幕不变；播放时转为 WebVTT。
- 复制或下载后可选生成 NFO。直接入库只读取原目录资料，不向原目录写入 NFO 或海报。
- 凭据使用 AES-GCM 加密保存，公开状态接口不返回凭据；修改接口校验本页面令牌和来源。

## 百度网盘接入

这是使用百度开放平台的实现，**不内置公共应用密钥，不提供免授权或绕过限速接口**。

在「添加来源 → 百度网盘」中，默认使用 **登录并授权百度网盘**：

1. 应用已配置时，点击登录，使用百度网盘 App 扫码确认，或在当前设备打开百度官方授权页，并按提示输入设备码。
2. 映库使用官方设备码 OAuth 获取授权，网页自动显示授权完成，不用复制授权码、Access Token 或 Refresh Token。
3. 点击「保存并连接」，目录验证成功后保存来源。已有来源可点击「重新登录」更新授权；令牌继续加密保存并按原逻辑自动刷新。

百度应用凭据仍然由部署者提供一次。项目配置为空时，会优先复用正在编辑的百度来源中的应用配置；也可复用已有唯一应用配置。首次部署或多应用有歧义时，展开 **部署者设置：百度应用（仅需一次）**，保存自己的 App Key 和 Secret Key。项目配置加密保存在 `data/`，也支持通过 `YINGKU_BAIDU_CLIENT_ID` / `YINGKU_BAIDU_CLIENT_SECRET` 环境变量提供。不借用第三方项目的应用密钥。应用必须具备网盘及设备授权权限；配置不完整时，页面会明确提示，不显示虚假的一键授权成功。

设备码模式不需要浏览器回调，手机访问局域网地址时同样可用。登录会话在服务内存中短期保留，支持取消、过期重新获取和一次性保存；未完成或取消的登录不会修改来源。完整登录流程和保存连接已用模拟账号验证，真实百度应用的设备授权资格和账号下载权限仍需用部署者自己的应用验证。

在 **高级：手动授权码或令牌连接** 中，也保留原来的方式：

1. 填写自己的、已具备网盘读取权限的百度应用 App Key、Secret Key。
2. 点击「打开授权页面」，在百度页面完成授权，将授权码复制回映库。此流程要求应用支持 `oob` 回调。
3. 或在高级选项填写已获取的 Access Token / Refresh Token；自动刷新需要同一应用的 App Key 和 Secret Key。
4. 填写网盘目录，例如 `/影视`，保存并测试。

具体可申请的权限、账号下载速度和接口可用性由百度决定。实际账号的登录、目录和大文件下载仍需要用你的凭据验证。百度接口已通过模拟响应测试，但本次未接入真实个人账号。授权与下载失败会显示错误，不会显示虚构目录或成功结果。

参考：[百度网盘开放平台](https://yun.baidu.com/union/home)。

## 夸克网盘接入

在「来源 → 添加来源」选择 **夸克网盘**：

1. 点击 **获取夸克登录二维码**，用夸克手机 App 扫码并确认。网页会自动接收登录结果，不需要打开开发者工具或复制 Cookie。
2. 页面显示登录完成后，点击「保存并连接」。映库先测试目录，再加密保存登录态；未保存的登录不会添加来源。
3. 默认连接整个网盘。需要限制范围时，可展开「限制可浏览的目录」填写起始文件夹 ID（默认 `0`）。只连接某个子目录时，填写夸克网页该目录地址中的文件夹 ID；这里不是 `/影视` 这样的目录路径。
4. 随后可以分别打开 `movie`、`tv`，浏览目录、选择视频或整目录扫描，确认作品匹配后下载入库。单个目录最多读取 10000 个条目；递归扫描仍沿用 1000 个视频、1200 个目录和 20 层子目录的限制。

夸克扫码模式属于网页登录，底层仍取得 Cookie，不把它称为映库的独立第三方 OAuth 授权。二维码在本机用纯 Go 库生成，不向第三方二维码服务发送登录内容；服务端与夸克官方登录域名通信，使用独立临时 Cookie 会话。取消、超时和关闭窗口会停止轮询，确认后的凭证只能用于对应来源的一次保存。扫码接口不可用时，可展开 **高级：手动使用 Cookie 连接**，按内置说明继续使用原方式。

Cookie 等同登录授权，只填写到自己的映库服务中，不要发送到聊天或公开截图。它使用现有本机密钥加密保存，不在公开状态接口、表单回显或错误中展示。编辑来源时留空保留；网页接口返回更新后的登录 Cookie 时会加密保存。登录态过期后需重新登录网页版，在来源设置中更新 Cookie。

当前采用夸克网页接口，并非公开开放平台 OAuth 授权；不需要额外部署 OpenList、Node.js 或浏览器自动化服务。支持下载原文件、暂停重试、带校验的断点续传和已有来源文件跳过，不提供分享转存、上传或删除网盘文件。下载通过运行映库的服务器进行，速度、大文件权限及接口可用性由夸克账号和网络决定。网页接口可能变化；不保证 Cookie 永久有效。

接口参数参考 [OpenList 夸克驱动说明](https://doc.oplist.org.cn/guide/drivers/quark) 与公开的扫码登录实现，适配器由本项目独立实现。二维码生成使用 `github.com/skip2/go-qrcode`，随 Go 程序编译。已用模拟接口验证扫码到保存连接的完整流程，以及目录翻页、跨季扫描、下载续传、重复跳过、失效登录态和凭据保护；真实夸克扫码入口已通过匿名生成与等待检查，本次未登录真实个人账号验证下载速度与大文件权限。

## 影片资料

扫描后的“待确认文件”支持多选、全选和批量归类为同一部剧。填写一次作品名称，或追加到本次扫描中已有的剧集分组；追加时保留已经确认的在线匹配，无需逐集检索。默认从文件名提取实际集号（例如 `07.4k.mp4` → 第 7 集），保留明确标注的季数与合并集范围；无法确定的集号留空，仍需核对。也可明确选择按文件名自然排序后连续编号，并指定统一季数与起始集号。批量操作先更新预览，不直接入库，不移动或改名原文件；重复、重叠及缺少集号仍由导入预览检查。

特别篇使用季数 `0`：支持 `S00E01`、`SP01`、`特别篇01`、`彩蛋第1集`，以及 `Specials`、`特别季`、`番外`、`彩蛋` 目录中的编号文件。明确的普通季集编号优先；特别篇与正片保留在同一部剧的不同季中。只有“彩蛋／花絮”等标记而没有集号的文件会留待确认，不随意按文件顺序猜编号，可批量归入季数 0 后补填。若要对应在线分集资料，应核对资料源的特别篇编号。

识别有误时，点击“用 AI 重新识别”，填写可选的补充说明，再点击“按说明重新识别”。可以直接描述正确作品名、季数、集号规则及彩蛋归属，例如“这些都是某剧第一季，前两位数字是集号；彩蛋目录归特别篇”。说明最多 2000 字，仅用于当前扫描，与目录名和相对文件名一起发给配置的 AI，每个批次都会带上；明确要求连续编号时提供全局文件排序序号，避免每批从 1 开始。用户明确提供的首播年份也可保留。成功后以新结果替换本次预览并重新确认作品；调用失败则保留原预览、手动修改和已有作品匹配。填写或收起说明不触发调用，不直接入库或修改原文件。

默认可以直接检索，不需要 API Key：

- **本地资料优先**：读取已有 `movie.nfo`、`tvshow.nfo`、`season.nfo`、分集 NFO、`poster` / `folder` / `fanart` 图片；只读原目录。在线补充不会覆盖 NFO 中明确提供的片名、简介、年份、导演等字段，空缺字段仍可自动获取。
- **电影与中文条目**：使用维基百科的公开接口获取简介和图片，Wikidata 补充结构化上映/首播日期、原名、演员、导演、编剧、地区、语言、制作公司及外部编号。年份不再从剧情中随便出现的数字推断。
- **剧集**：同时检索 TVmaze 和百科。百科条目通过 Wikidata 的 TVmaze/IMDb 编号与 TVmaze 关联，补充全剧与每季的日期、分集信息、角色和人物照片，不凭相似名称拼接不同作品。部分简介、角色名和人员职位为英文。
- **年份分开记录**：整部剧的年份是其首次播出年份；各季的年份和首播日期来自季资料或分集日期。导入时年份可以留空，匹配后补齐；同名翻拍仍可用年份辅助区分。
- **已有库自动补充**：开启“导入后自动补充影片资料”时，升级后会在后台给旧条目补充新字段。也可在详情点击“补全资料”；“匹配作品”用于纠正作品身份。补全只读取原视频目录资料，不重新下载视频。
- **自动匹配**：导入后后台补充资料。名称、年份不足以确定作品时保留原名称，提示手动选择，不随意套用第一条结果。
- **可选 TMDb**：在「设置 → 高级：使用 TMDb」填写自己的 [API 凭据](https://www.themoviedb.org/settings/api) 后，检索优先使用 TMDb，无结果时补充检索百科与 TVmaze。支持 v3 API Key 或 API Read Access Token。清除凭据即可恢复直接检索公开资料源。

不同资料源的收录、中文翻译、评分与分集信息不完全一致。百科源不保证提供评分或每集资料；需要完整 TMDb 数据时仍需使用自己的应用凭据。Jellyfin 的免填写体验来自其项目内置的应用凭据，本项目没有借用其他项目的凭据。

作品详情保留来源链接与许可提示。TVmaze 内容采用 CC BY-SA；维基百科文字与图片的许可见原条目，Wikidata 结构化数据使用其公开许可。本产品使用 TMDb API 时，未经 TMDb 认可或认证。

## 当前范围

- 已入库视频会在后台检查文件是否存在、可读取；影视墙和剧集页标记失效文件，正在下载的视频不按缺失文件处理。可点击“检查文件”重新检查；离线存储不会触发自动移除。每轮最多两个文件检查同时进行，不在读取媒体库状态时等待文件系统。
- 失效视频提供重新定位、重新检查和移除记录入口。重新定位填写服务器上的完整视频路径（容器部署填写容器内路径），只更新关联，保留原作品、季集、观看进度和字幕记录；不会移动、重命名或下载原文件。新路径必须可读取且不能已被其他视频记录占用，下载运行或投屏使用中的文件需先停止相关操作。存储暂时未挂载时应先恢复挂载再检查。

- 个人、单进程使用。默认统一监听 0.0.0.0:8787，本机与局域网共用同一服务端口；网页密码保护可选。反代域名访问不依赖 YINGKU_PUBLIC_URL，它只覆盖页面展示地址。保留同源检查、页面令牌和直接连接的本机/私网范围检查；不把代理传来的访客地址当成本机管理权限，没有公网多用户权限管理。
- 浏览器直接播放；推荐 MP4 / H.264 / AAC。其他容器、编码和音轨是否能播放取决于浏览器与系统。尚无实时转码、HDR 转换或 ASS/PGS 特效字幕。
- 支持当前目录及子目录批量扫描、多作品归类和跨季导入，也可保留单部作品的手动导入方式。扫描后先预览确认，暂不持续监视整个磁盘。
- 本地默认直接入库并依赖原视频路径，之后移动或删除原视频会影响播放。可主动切换为复制整理；不会自动订阅资源站点、转存分享链接或进行 BT 下载。
- 移除本地来源时，同时移除该来源的媒体库视频记录；作品仍有其他来源的视频时继续保留。所有磁盘文件都保留。移除网盘或 WebDAV 连接继续保留已下载的影片和入库记录。有未完成或仍在收尾的任务时需先完成或取消。升级后会备份并清理旧版遗留的、来源已不存在的本地直接入库记录，不清理已下载或复制的视频记录。
- 作品详情的“更多作品操作”可单独移出电影或整部剧；季标题旁可移出本季，每集“文件与字幕”中可移出该视频。默认仅清理入库记录、相关下载任务、观看进度和字幕关联，所有磁盘文件和来源配置保留；移出最后一个视频后作品也会消失。合并多集的视频会一并移出所含集数。正在下载、入库或收尾的任务需先停止并等候结束；排队任务随记录移除。
- 媒体移除窗口另有默认不勾选的“同时永久删除服务器上的视频文件”。先展示服务器文件清单，再明确确认；本地来源删除原视频，网盘来源只删除本机下载副本和列出的下载临时文件，百度、夸克云端原文件与来源配置始终保留。外置字幕、海报、NFO 保留。不删除目录、链接、仍被其他记录引用或正在投屏的文件。文件变化或确认过期时需要重新预览。保存记录失败会恢复文件；服务中断后会按持久化记录完成清理或恢复，遇到冲突保留文件并在页面提示，不覆盖新出现的同名文件。
- 下载页支持多选、全选当前筛选结果、作品／文件名搜索，以及独立的“等待下载”“已取消”等筛选。可批量暂停、继续、取消，或停止下载后移除任务记录；批量停止同时阻止所选排队任务启动，并等待相关下载收尾。移除下载任务记录始终保留所有磁盘和网盘文件；已完成任务只清理下载历史，已入库影视保留。正在入库和状态已变化的任务会跳过并说明原因。
- 播放器显示“原画 · 宽 × 高”，尺寸由浏览器实际读取并保存，之后可在该视频的“文件与字幕”中查看。读取分辨率无需转码或额外安装 FFmpeg；旧视频首次成功加载播放资料后补充。浏览器无法读取的视频显示“分辨率未知”，不根据文件名猜测，不提供尚未生成的清晰度档位。
- 顶部影视导航与设置入口在所有页面保持一致；管理侧栏仅包含来源、下载任务和设置，返回影视库统一使用顶部入口。影视墙和作品详情继续全宽展示。电视剧播放器提供上一集、下一集，按季集顺序切换并先保存当前进度；可跨季，首末集及相邻未入库视频显示明确提示并禁用，不跳过未完成的视频。返回作品时定位到正在播放的季。
- 播放器使用统一的画面内浮层控件：进度、播放暂停、上下集、音量、原画尺寸、字幕与倍速、投屏和全屏。不再额外占据视频下方空间；播放时自动隐藏，操作或暂停时显示。支持浏览器容器全屏时，整套控件随播放器进入全屏，切换上下集保持全屏；不支持该接口的浏览器继续使用网页内全屏布局。视频仍为直接播放，不转码。
- 全屏和非全屏播放中，鼠标或键盘停止操作约 2.8 秒后自动隐藏标题和控制栏；播放区域保有键盘焦点不阻止隐藏，操作时重新显示。暂停、缓冲、打开播放设置或拖动滑块时保持可见。长按倍速提示使用顶部小提示条，不覆盖画面中央。
- 电视剧播放结束后倒计时 5 秒连播下一集，可取消、立即播放，或在播放设置中关闭；开关保存在当前浏览器。下一集未入库时只提示，不跳过该集。手动或自动切集复用视频元素，保持全屏与倍速偏好。浏览器如限制自动播放，会提示点击播放继续。
- 网页播放区支持触摸／触控笔手势：播放中长按约半秒临时至少 2 倍速，松手、取消触摸或离开页面时恢复原速度；左右滑动预览快进快退，松手后跳转，取消触摸不改变进度。手势只接管视频画面，控制栏、进度条和设置菜单继续按各自方式操作。浏览器或系统接管的原生全屏播放器仍使用其自身手势。
- 电脑播放器支持键盘：右方向键短按在松开时快进 5 秒；播放时按住约半秒临时至少 2 倍速，松开恢复原速度，不叠加快进；左方向键快退 5 秒。上下方向键每次调整播放器音量 5%，支持连续按住、静音和取消静音，显示实际音量百分比。输入框、滑块、下拉菜单等控件保留原生按键行为。暂停、结束、失去焦点、切换窗口或关闭播放器会撤销临时倍速；空格 / K 播放暂停、M 静音、F 全屏继续有效。
- 视频左半区上下滑即时调整画面亮度（20%–150%，默认 100%），右半区上下滑调整播放器音量；上滑增大、下滑减小，显示实际百分比，触摸起点决定左右区域，识别方向后不切换操作。竖向手势不会跳进度或触发暂停、倍速。画面亮度仅改变视频显示，不改变设备系统亮度，也可在播放设置中恢复到 100%；切集保留当前页面的亮度偏好。浏览器拒绝网页调整音量时提示使用设备音量键。
- 播放器投屏按钮位于顶部右侧，使用屏幕与无线信号图标。设备选择在播放器上方，成功后进入独立遥控页面并暂停网页播放。返回时恢复原播放器与进度，不自动在网页发声；刷新遥控页后仍能控制电视，再返回作品。离开遥控页不停止电视或连播。
- 取消任务保留临时文件，可再次继续；移除任务记录后仍保留所有文件。媒体库默认仅移出记录，只有明确勾选并确认文件删除选项时才删除列出的服务器视频。暂不提供清理所有缓存或删除网盘云端文件的操作。
- 默认使用本机 JSON 快照保存配置、媒体和任务，每次通过临时文件同步落盘后替换；适合个人小型媒体库。后续可迁移 SQLite。
- 可在家中电脑或 NAS 上运行 Go 服务供局域网使用；多个用户、大型媒体库、跨网投屏和已有 Jellyfin 客户端兼容不在本版本范围。

## 数据与备份

默认 `data/` 位于启动目录，也可通过 `-data` 或 `YINGKU_DATA_DIR` 指定。容器镜像默认使用 `/config`。默认下载目录可以在网页设置中更改，或由 `-media` / `YINGKU_MEDIA_DIR` 固定；启动配置只更改以后导入的位置，不移动旧视频。

```text
data/
  state.json     配置、来源、任务、媒体和观看进度
  secret.key     加密密钥，必须与 state.json 一同保管
  media/         默认媒体下载位置，可在设置中更改
  art/           海报与剧照缓存
  subtitles/     导入的字幕
```

停止程序后备份完整 `data/`；直接入库的原视频，以及下载到其他磁盘的视频，需分别备份。旧版资料会自动升级，已有下载、来源和观看进度保留；不会自动移动旧视频。不要把包含真实账号数据的 `data/` 放入代码仓库。请勿同时使用两个实例打开同一份数据目录。

0.4 升级补充资料前会额外保存 `state-before-details-v4.json`。该备份与 `secret.key` 配套保管。只读入库的原视频与 NFO 不会写入改动；参考时长来自资料源或 NFO，不等于对实际文件的技术探测结果。分辨率、编码、音轨、HDR 和章节等媒体技术信息尚未探测。

0.5 升级前保存 `state-before-ai-v5.json`，AI 默认未启用，不会自动发送现有库的目录。原有来源、视频路径、观看进度、字幕和任务继续保留。

0.6 升级前保存 `state-before-network-v6.json`。局域网默认关闭，需要用户在电脑上主动开启。0.6.1 起密码为可选项，旧版已有密码保护继续保留。扫描记录、登录会话与投屏会话保存在内存，重启后投屏与启用了密码保护的登录需重新建立；来源、任务与观看进度正常持久保存。

0.7 升级前保存 state-before-listener-v7.json。服务改为默认监听 0.0.0.0:8787，移除旧的局域网开关与第二端口设置，访问密码选项保留。已有来源、视频路径、观看进度和任务不变。重复启动仍会打开已运行服务的可访问地址。

升级到 0.3 后会自动归并能够确定为同一作品的重复剧集。首次实际归并前，将原始状态保存为 `data/state-before-series-v3.json`。归并只修改媒体库中的父子关系，文件 ID、季集号、原路径、观看进度、字幕和任务不变；原条目 ID 会保留映射。相同名称但不同已知首播年份或冲突资料编号的作品不会自动合并，“新建独立剧集”也会保留独立。确需恢复时，先停止服务，再用该备份替换 `state.json`，并使用归并前版本；新版本会重新执行确定的归并。

## 源码开发

需要 Go 1.24 或更新版本。唯一第三方 Go 依赖是用于本地生成二维码的 `github.com/skip2/go-qrcode`，许可见 `THIRD_PARTY_NOTICES.md`。

```sh
go run .
go test ./...
go vet ./...
go build -trimpath -ldflags="-s -w" -o yingku.exe .
```

Linux / macOS 构建时可改为 -o yingku。可通过 -addr 0.0.0.0:8788 更换统一端口，-addr 127.0.0.1:8787 限制为本机访问，-data /absolute/path 更换资料目录，-media /absolute/path 固定默认下载目录，-public-url https://media.example.com 设置部署地址，-open 在启动后打开浏览器。对应的环境变量和优先级见容器部署说明。

主要文件：`sources.go`（来源适配）、`import.go`（分集与导入）、`download.go`（任务与传输）、`metadata.go`（TMDb / NFO 导出）、`public_metadata.go`（无需 Key 的在线资料）、`local_metadata.go`（只读本地 NFO 与海报）、`model.go`（资料保存与凭据）、`main.go`（HTTP 与启动）、`web/`（内嵌界面）。
